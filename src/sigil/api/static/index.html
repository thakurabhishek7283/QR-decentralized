Sigil

Check that a product is genuine — and check the checker. Every label is signed, publicly logged, and carries a pattern a photocopier cannot reproduce.

1Pick a label

Labels come from a batch the manufacturer issued. Each carries a unique signed credential.

Issue a new batch

Issuing signs each credential, appends it to the transparency log and samples the batch’s print quality. It needs the server’s API key.

2Photograph it

Nobody can hold a label up to this page, so the print-and-camera channel is simulated with the same physical model the detector is evaluated on. Pick what ends up in front of the camera.

What gets photographed

Tip: scan one label from Mumbai, then from London a moment later. No genuine item can travel that fast, so Sigil flags a clone.

3Verdict

Don’t trust the server

Every credential is in a public append-only log (RFC 9162, as in Certificate Transparency). Your browser can check the maths itself with WebCrypto.

Loading the log…

The log’s public key is fetched from this same server. A real witness pins it out of band: sigil audit --log-key.

Inclusion of the selected label

Recomputes the leaf from the QR text, then folds the proof up to the signed root.

Append-only since you last looked

Your browser remembers the last tree head it saw and asks for a consistency proof to the current one.

How it decides

Deterministic first. Signature, key status, log inclusion, the copy-detection score and clone analytics feed a fixed policy table. Most scans end there, in about 150 ms.

Agent only when unsure. An investigator calls tools to gather more evidence, may ask for a retake, and must cite what it found. A policy bounds what it may conclude, so it can never overrule a failed signature.

Everything is recorded. Each run is a hash-chained trace you can replay offline.
